# 支付订单故障诊断演示材料

本目录用于 `IncidentPilot` 的本地演示。所有订单号、日志、金额和处理结论均为模拟数据，不应连接真实支付系统。

## 目录约定

- `knowledge/`：可上传到 Cognida「支付系统故障知识库」的 RAG 文档。
- `evaluation/`：开发评测案例与金标准。**不得上传到知识库**，否则会使评测答案泄漏。

## 导入顺序

1. 在前端创建知识库，名称填写「支付系统故障知识库」。
2. 上传 `knowledge/` 下的 5 个 Markdown 文件。
3. 在知识库助手中提问，并检查回复是否引用相应文档与段落编号。
4. 使用 `evaluation/payment_incident_dev_cases.json` 中的案例逐条验证，记录实际工具轨迹、耗时、Token 和结论。

## 演示约束

- `replay_payment_callback` 是有副作用的操作，必须先生成待审批草稿；未经确认不得执行。
- 相同 `idempotency_key` 的回放只能成功一次，重复请求应返回已有执行结果。
- 无法获得订单、支付或回调证据时，Agent 应明确说明证据不足，而不是猜测根因。
