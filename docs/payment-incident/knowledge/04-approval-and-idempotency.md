# 回调回放审批、幂等与恢复规范

文档 ID：`PI-KB-004`  
版本：`v1.0`  
生效日期：`2026-01-01`  
适用范围：支付补偿类有副作用操作

## 1. 审批边界

【PI-KB-004-1】`replay_payment_callback` 是写操作。Agent 只能基于诊断证据生成回放草稿，草稿状态为 `awaiting_approval`；只有人工明确确认后，执行器才能调用回放接口。

【PI-KB-004-2】审批内容必须绑定 `order_id`、`payment_id`、`callback_id`、预计动作、诊断证据和 `idempotency_key`。用户改变任意订单范围、支付流水或动作参数后，旧审批失效，必须重新生成草稿。

## 2. 幂等要求

【PI-KB-004-3】同一补偿动作使用稳定键 `replay:{payment_id}:{callback_id}`。执行器以该键查询已有执行结果：若已成功，直接返回既有结果；若执行中，返回执行中状态；不得二次发送回放请求。

【PI-KB-004-4】请求超时或响应丢失时，先按 `idempotency_key` 查询执行记录，再决定是否重试。禁止因为客户端未收到响应就创建新的回放键。

## 3. 完成验证与审计

【PI-KB-004-5】回放成功后校验订单状态、支付记录、回调消费记录与业务事件。验证失败时将动作标记为 `failed` 并保留原始证据；不得只依据接口响应判断成功。

【PI-KB-004-6】审计日志至少包括发起人、审批人、时间、输入摘要、证据引用、`idempotency_key`、执行结果和恢复尝试次数。
