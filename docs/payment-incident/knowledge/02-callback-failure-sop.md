# 支付回调失败处理 SOP

文档 ID：`PI-KB-002`  
版本：`v1.0`  
生效日期：`2026-01-01`  
适用范围：支付渠道回调接收、验签与订单状态更新

## 1. 回调处理状态

【PI-KB-002-1】支付渠道回调依次经过：接收请求、验签、去重、订单状态更新、业务事件投递。日志中的 `signature_invalid`、`duplicate_ignored`、`order_not_found`、`db_timeout` 与 `event_publish_failed` 分别代表不同故障类型，不能统一按“回调失败”处理。

【PI-KB-002-2】`duplicate_ignored` 在已存在相同成功处理记录时是正常幂等结果，不属于故障；只有支付渠道成功、订单未更新且无成功消费记录时，才需要进入补偿流程。

## 2. 诊断与处置

【PI-KB-002-3】先调用 `search_callback_log(payment_id)`，确认渠道回调 ID、验签结果、HTTP 响应、消费状态与失败原因。再调用 `query_order_status(order_id)`，确认订单当前状态与版本。需要回放前，必须确认支付记录状态为 `SUCCESS`。

【PI-KB-002-4】失败原因为瞬时网络错误、数据库超时或事件投递失败，且满足“支付成功、订单未支付、无成功消费记录”三个条件时，可创建 `replay_payment_callback` 的待审批草稿。回放应携带原始 `payment_id`、原始 `callback_id` 和稳定的 `idempotency_key`。

【PI-KB-002-5】失败原因为验签失败、订单不存在、金额不一致或回调载荷不完整时，禁止回放。应保留原始请求摘要并升级人工排查，因为重放相同载荷不能修复业务数据或安全校验问题。

## 3. 验证

【PI-KB-002-6】回放完成后必须再次查询订单与回调日志。成功标准是订单变为 `PAID`、回调消费记录为成功且仅存在一条有效状态更新；只收到 HTTP 200 不能作为成功依据。
