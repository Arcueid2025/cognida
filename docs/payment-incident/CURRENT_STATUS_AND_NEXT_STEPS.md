# 支付故障核验平台：当前状态与后续工作

更新日期：2026-09-06

## 当前定位

项目目前是一个**受证据约束、人工主导的支付故障核验原型**。它能检索支付知识、生成安全核验建议并管理人工案件；不会读取真实支付系统，也不会执行补单、回调回放、关单或订单状态修改。

```text
故障描述 / 订单号
        ↓
混合检索与可追溯证据
        ↓
核验建议（无证据则人工升级）
        ↓
人工创建案件与状态流转
        ↓
审计留痕
```

## 已完成工作

### 阶段 A：检索质量与评测基础

- Docker Compose 本地环境已运行：Vue 前端、Go API、Python 服务、MySQL、Milvus、Neo4j、Redis、MinIO。
- Milvus 已使用中文分析器，支持向量、BM25 和混合检索。
- 已建立 5 份支付故障知识文档、11 个知识分块和 20 条开发评测用例。
- 已建立 12 条独立保留评测用例，避免只报告开发集结果。
- 离线评测脚本支持 `vector`、`bm25`、`hybrid`，并可通过 `--rerank-variants off,on` 生成重排 A/B 对比。
- A/B 报告会输出 Recall@K、P95 延迟、API 错误数及差值建议；尚未因为重排指标未完成实际对比而启用线上重排。

已知开发集基线（20 条自建用例，仅作原型横向对比）：

| 模式 | Recall@5 | 平均延迟 | P95 延迟 |
|---|---:|---:|---:|
| 向量检索 | 56.25% | 173.51 ms | 251.74 ms |
| BM25 | 55.00% | 11.48 ms | 16.43 ms |
| 混合检索 | 58.75% | 162.14 ms | 211.77 ms |

### 阶段 B：受证据约束的核验建议

- 已提供“支付故障核验台”页面，支持订单号或故障描述检索。
- 已展示原始证据、来源文档、相对匹配度和查询词高亮。
- 已生成固定结构的建议：故障判断、已知事实、待核验项、建议动作、风险提示、引用证据。
- 只有片段含 `PI-KB-xxx-x` 可追溯编号时才给出规则约束建议；无结果或无引用时固定提示“信息不足，建议人工升级”。
- 核验台检索请求会写入用户问题、检索配置、证据快照和 `evidence-bound-v1` 规则版本到既有审计链。

### 阶段 C：人工案件流 MVP

- 已新增 `payment_incidents` 数据库迁移，当前迁移版本为 `5` 且 `dirty=false`。
- 已实现案件状态机：

  ```text
  待核验 → 处理中 → 待确认 → 已解决 / 已升级
  ```

  已解决和已升级为终态，后端拒绝非法跳转。

- 已实现案件创建、当前租户案件列表与状态流转 API。
- 已在核验台接入“人工案件”界面；用户可手动创建案件、刷新列表并选择合法状态流转。
- 已验证案件创建、列表显示及“待核验 → 处理中”流转；页面不会自动创建案件，也没有任何资金操作入口。
- 创建和状态变更会写入审计快照。

## 下一步开发顺序

### 1. 完成阶段 C 案件闭环

1. 增加案件详情页，展示订单号、类型、优先级、状态、创建时间和责任人。
2. 创建案件时自动关联本次核验的审计 `request_id`、检索证据和建议规则版本。
3. 增加案件时间线：创建、状态变更、人工结论、附件和审计链接。
4. 支持责任人分配与人工结论记录。

验收标准：从核验检索进入案件后，可在同一案件详情看到原始证据、建议版本、每次状态变化和操作者；当前租户不能查询或修改其他租户案件。

### 2. 完成阶段 A 的重排决策

1. 运行开发集和保留集的 `hybrid` / `hybrid+rerank` A/B 报告。
2. 比较 Recall@5、P95 延迟和错误率。
3. 仅在保留集 Recall@5 有提升且延迟、错误率可接受时启用重排。

验收标准：两份结果文件均可复现、保留集与开发集分开报告；没有 Recall 增益时保持线上重排关闭。

### 3. 阶段 D 前置：模拟只读支付工具

1. 建立模拟订单、支付记录和回调日志数据。
2. 接入只读工具：订单查询、支付流水查询、回调日志查询。
3. 让 Agent 以工具返回的事实补充知识检索结果。

验收标准：每个关键结论都能同时追溯到知识规则或模拟工具事实；证据不足时只允许人工升级。

### 4. 阶段 D：审批、幂等与审计

1. 高风险动作只生成待审批草稿。
2. 加入角色权限、二次确认和稳定幂等键。
3. 全量记录申请、审批、执行结果、请求 ID 和验证结果。

验收标准：无审批不得执行；同一幂等键不会产生重复副作用；先在模拟系统完成端到端验证。

## 当前演示步骤

1. 打开 `http://localhost:8888`，进入“支付故障核验”。
2. 输入支付异常描述并点击“检索证据”。
3. 查看受证据约束建议；无引用时应显示人工升级提示。
4. 手动点击“创建案件”。
5. 在“当前租户案件”中将案件从“待核验”转为“处理中”。
6. 在审计日志中查看对应的检索或案件事件。

> 所有订单号、知识文档、案件和处理结果均为本地模拟演示数据，不应连接真实资金系统。
